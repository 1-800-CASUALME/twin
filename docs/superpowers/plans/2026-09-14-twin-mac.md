# Twin macOS App (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A native SwiftUI installer-style app, Twin.app, that drives the `twin` CLI through its six screens: Welcome, Connect, Diagnose, Choose, Sync, Done.

**Architecture:** Swift Package (executable target) so it builds with `swift build` and no Xcode project. `TwinCore` spawns the bundled `twin` binary with `Process`, parses NDJSON lines into `Event` values, and feeds an `@Observable AppState`. Views are thin: each screen renders state and calls one action. `build.sh` assembles `Twin.app` with an Info.plist and the release `twin` binary inside `Contents/MacOS`.

**Tech Stack:** Swift 6, SwiftUI, macOS 15+, SF Symbols, Foundation Process. No third-party packages.

**Spec:** `docs/superpowers/specs/2026-09-14-twin-design.md` §2.2, §3, §4.

## Global Constraints

- System font, system materials, SF Symbols only; the only color is the accent color and the semantic green/amber/red for states.
- Window is fixed at 760x500 with a step sidebar on the left and Back / Continue at the bottom, like a macOS installer.
- Every syncable item is an icon card with name, count, size, location; cards expand to members with checkboxes; Select All at the top.
- Loading states use `ProgressView` and `.symbolEffect(.pulse)`.
- The app must work with `twin` at `Bundle.main.executableURL.deletingLastPathComponent()/twin`, falling back to `~/.local/bin/twin` and `/opt/homebrew/bin/twin`.
- On first launch the app symlinks `~/.local/bin/twin` to the bundled binary so SSH sessions from the peer can find it.

## File structure

```
mac/
  Package.swift
  Info.plist
  build.sh                          builds core (release) + swift build + assembles Twin.app
  Sources/Twin/
    TwinApp.swift                   @main, WindowGroup, fixed size
    Model/Event.swift               Codable mirror of the core's NDJSON events
    Model/TwinCore.swift            runs `twin <args>`; AsyncStream<Event>; stdin writer
    Model/AppState.swift            @Observable state machine for the six steps
    Views/RootView.swift            sidebar + content + bottom bar
    Views/WelcomeView.swift
    Views/ConnectView.swift         Find button, peer list, code sheet
    Views/DiagnoseView.swift        check grid with Fix buttons
    Views/ChooseView.swift          item cards, Select All
    Views/SyncView.swift            per-item progress, conflicts
    Views/DoneView.swift            summary, schedule toggle, attach hint
    Views/Components.swift          StatusDot, IconCard, Spinner, ByteFormatter
```

### Task 1: Core addition `twin select` (persist selection)
- Add `Select { items: Vec<String>, #[arg(long)] member: Vec<String>, #[arg(long)] autocommit: Vec<String> }` to the CLI: writes `selection`, `git_autocommit` into `~/.twin/config.toml`. Test: `twin select claude git --autocommit code/habits` then `cat ~/.twin/config.toml`.
- Commit.

### Task 2: Package, Event, TwinCore
- `Package.swift`: tools 6.0, platforms macOS 15, one executable target `Twin` at `Sources/Twin`.
- `Event.swift`: `enum Event: Decodable` keyed on `ev` with cases step, progress, conflict, peer, code, item, check, done, error, matching the Rust field names exactly.
- `TwinCore.swift`: `static func binaryURL() -> URL`, `func run(_ args: [String]) -> (AsyncStream<Event>, ProcessHandle)` where `ProcessHandle` has `write(_ line: String)` and `terminate()`. Lines that fail to decode are logged and skipped.
- Verify: `swift build` succeeds.

### Task 3: AppState
- `@Observable final class AppState`: `step: Step` (welcome, connect, diagnose, choose, sync, done), `peers: [PeerInfo]`, `pairingCode: String?`, `paired: PeerStatus?`, `checks: [CheckResult]`, `items: [Item]`, `selectedMembers: Set<String>` (keys `item:member`), `selectedItems: Set<String>`, `progress: [String: (done: Int, total: Int)]`, `stepStates: [String: StepState]`, `conflicts: [Conflict]`, `busy: Bool`, `error: String?`, `daemon: ProcessHandle?`.
- Actions: `startDaemon()`, `discover()`, `pair(peer:)`, `confirmCode(_ yes: Bool)`, `diagnose()`, `fix(id:)`, `inventory()`, `toggle(item:)`, `toggle(member:)`, `selectAll()`, `sync()`, `setSchedule(_:)`.
- `canContinue` per step: connect requires `paired != nil`; diagnose requires no `.fail` in checks; choose requires a non-empty selection.

### Task 4: Views
- `RootView`: `HStack { Sidebar (200pt, `.ultraThinMaterial`, steps with SF Symbols and a checkmark when passed) | content }` with a bottom bar `Back` / `Continue` (`.keyboardShortcut(.defaultAction)`).
- `WelcomeView`: app symbol `arrow.triangle.2.circlepath` at 72pt with `.symbolEffect(.pulse)`, title "Twin", one line, Continue.
- `ConnectView`: one big button "Find the other machine" (`magnifyingglass`), spinner while browsing, peer rows (`desktopcomputer` / `laptopcomputer` by OS) that start pairing on click; sheet showing the 6-digit code in `.largeTitle.monospacedDigit()` with "Same code?" Confirm / Cancel; on success a green `checkmark.circle.fill` with the peer name. Link "Away from home?" opens Tailscale docs.
- `DiagnoseView`: one button "Check both machines" (`stethoscope`), then a `LazyVGrid` of check cards: icon from the core's `CHECKS` icon names, name, side badge (This Mac / Peer / Pair), StatusDot, message, Fix button when `fixable`. For `ssh` on the local side the Fix opens `x-apple.systempreferences:com.apple.preferences.sharing?Services_RemoteLogin`.
- `ChooseView`: "Select All" toggle at the top, `LazyVGrid` of `IconCard`s (Claude, Git, plus disabled cards for Dotfiles, History, Terminal, Folders labeled "Soon"). Card: icon, name, count, size, location; a disclosure reveals members with a checkbox each, member name, detail, size, and two small dots showing presence on this Mac and on the peer.
- `SyncView`: one button "Sync" (`arrow.triangle.2.circlepath`), then per-selected-item rows with an animated symbol while running, `ProgressView(value:)`, final message, and a conflicts list.
- `DoneView`: `checkmark.seal.fill` 72pt, summary lines, Toggle "Keep in sync every 15 minutes" (calls `twin schedule on|off`, shown disabled with "Phase 4" until the core has it), "Sync again" button, and the `twin attach` hint.

### Task 5: Bundle
- `Info.plist`: CFBundleIdentifier `com.asim.twin`, CFBundleName Twin, LSMinimumSystemVersion 15.0, NSHighResolutionCapable, CFBundleIconFile Twin.
- `build.sh`: `cargo build --release -p twin`, `swift build -c release`, assemble `build/Twin.app/Contents/{MacOS,Resources}`, copy both binaries and Info.plist, generate `Twin.icns` from an SF Symbol rendered by a tiny Swift script if `iconutil` exists, `codesign --force --deep -s -` (ad hoc).
- Verify: `open build/Twin.app` shows the Welcome screen; `twin diagnose --local` works from the bundle path.
